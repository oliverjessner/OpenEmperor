# Architecture

The application shell keeps command-line validation in `src/app/main.cpp`, SDL initialization and lifecycle in `src/app/Application.cpp`, and rendering in `src/renderer/TitleScreen.cpp` and `src/renderer/ImagePreview.cpp`. The shared asset library uses `src/assets/Sg3Archive.cpp` for independent, bounds-checked SG3 metadata parsing and type classification; `src/assets/Sg3ImageLoader.cpp` reads the metadata table, resolves safe `.555` paths, and independently validates and reads the selected color and alpha ranges. It dispatches plain RGB555 images to `Sg3RgbaDecoder.cpp`, Sprite types 256/257/276 to `Sg3OmegaDecoder.cpp`, and Type 30 to `Sg3IsometricDecoder.cpp`. The latter draws the validated diamond-tile base and applies an optional Omega color overlay into the same RGBA buffer. After color decoding, the loader applies an optional version-214 Omega alpha stream using `Sg3AlphaDecoder.cpp`; skips retain existing alpha and literals replace only the A channel. This library has no SDL dependency. The inspector uses `tools/asset-inspector/main.cpp` for command dispatch and `tools/asset-inspector/Sg3Inspect.cpp` for metadata JSON, compact summary, separate bitmap range reports, and optional exports; it calls the shared loader rather than owning runtime file-loading logic. `src/assets/RgbaPngEncoder.cpp` writes PNGs for inspection, and `src/assets/RgbaPngReader.cpp` reads this project's exported PNG subset for debugging preview.

Future game-data discovery and importing belong in `src/assets/` and `tools/importer/`. General reusable types belong in `src/core/`; platform-specific integrations belong in `src/platform/`. None of those modules contain game logic yet.

Without browser mode, an optional `--data` directory is only checked and reported. With `--sg3 <file> --image <index>`, the app calls the shared asset loader, obtains one `RgbaImage`, uploads its pixels directly to an SDL3 texture, and renders it centered. No PNG, raw RGBA file, or inspector-tool dependency is involved. `--preview <exported.png>` remains available for debugging. SG3 inspection reports documented metadata and associated bitmap bounds; its export command can write raw RGBA bytes or a PNG when explicitly requested. The texture uses straight RGBA and SDL blending. Malformed or out-of-bounds alpha streams fail rather than being corrected. Available real alpha-bearing files have unresolved visual discrepancies, and there is no local Type-30 alpha-bearing example; see the research log. The parsed mirror offset is not applied. Reverse-engineering evidence belongs in `docs/reverse/`, separate from implementation.

`src/assets/AssetCatalog.cpp` scans a user-supplied directory without decoding pixels. It records stable `AssetId` values as relative SG3 paths plus image indices, established SG3/group fields, separate color/alpha range statuses, and format support. Archives are sorted by relative path; malformed archives become errors while scanning continues. Directory symlinks and SG3 symlinks are not followed, and external `.555` paths reuse the loader's safe resolver. The `openemperor-assets` CLI filters records and emits a summary or metadata-only JSON without absolute local asset paths. Catalog `decoder_supported` is conservative for alpha-bearing records, while `color_decoder_supported` describes only their color layout.

`src/app/AssetBrowser.cpp` owns the SDL browser presentation. It starts from catalog metadata, decodes visible cells lazily through `load_sg3_image`, and uploads RGBA to nearest-neighbor SDL textures. A least-recently-used cache is bounded to 64 entries and 64 MiB, with a 16 MiB single-image limit. Decode errors stay attached to individual records and render as placeholders. The default view excludes unavailable/unsupported color records and alpha-bearing records with unresolved semantics; a toggle exposes all candidates. `--ignore-alpha` passes a diagnostic flag to the shared loader for color-only inspection. No image or thumbnail is written to disk, and the asset layer remains SDL-free.
