# Additional production: evidence and compatibility boundary

**RESEARCH_PARTIAL.** Further model rows can be inspected, but the consulted
contracts do not establish an additional complete original construction,
harvest, processing, transport and consumption chain. No new crop, recipe, World
rule, save schema or gameplay option is activated. The existing recommended
Rule18 economy and all historical generations retain their own behavior.

## What the sources establish

The [model provenance register](model-provenance.md) defines the source revision,
raw columns and checked difficulty arithmetic. A row's name and Cost/Employees
values are model facts. Cost is a component, not a complete general purchase
formula; Employees does not reconstruct worker allocation. Raw `Resource` has
unresolved identity/quantity semantics and cannot select an input, output or
recipe. `SZE` denotes desirability step size, not footprint side.

Generic `ModelData` access and the model inspector do not extend the named
prepared capability set. Original saved entity records likewise expose bounded
type, side, coordinates and source identities, not an admitted producer or a
decoded harvest lifecycle. Their NonHouse payload is not a source of inferred
crop timers, yields or parent/field ownership.

The existing [luxury-source contract](../reverse/original-luxury-source-contract.md)
separately identifies particular factory, material-selector and physical-return
paths. The [Food/consumption contract](../reverse/original-goods-consumption-food-contract.md)
establishes bounded House operations, not farm production or a calendar. Neither
allows unrelated candidates to inherit an existing recipe by name.

## Candidate register

The complete loaded model was reviewed by row identity and label to select the
agricultural, extraction, processing, storage/distribution and material-sink
candidates below. Submenus, unused rows, terrain/editor sources and construction
support are kept distinct. The tables retain only three raw numeric columns;
these are neither difficulty-prepared values nor a copied model table. Labels
retain source spelling, including `Confucian Academny`.

`E1/E2/E3` describes an **existing authored World** side of 1/2/3 tiles;
`F1/F2` describes an existing functional adapter with that World side. Neither
establishes a new original purchase footprint. Existing plant/field attachment,
materials and sinks are qualified in the paid-path table below. `U` means no
purchasable World kind: original footprint, attachment, recipe/input/output,
quantity, period, capacity, route and demand remain **UNKNOWN** in these consulted
contracts. No missing field is filled from a nearby row or from `Resource=0`.

## Why no additional original chain is selected

An additional Field label does not establish its parent Farm, physical side,
terrain/fertility admission, price transaction, harvest clock, yield, Food score
or season. A mine, fishery or processing label similarly does not establish its
resource-search predicate, actor work/return phases, recipe units, finite buffers
or downstream demand. Reusing the existing 80-tick period or creating stock from
`Resource` would add authored behavior while falsely presenting it as recovered
original production.

The existing Logging and Orchard evidence includes real harvesting actors and
returns, but leaves growth, tending, regeneration and calendar unresolved. The
Smelter evidence requires internally extracted material without establishing a
complete external mining ecology. None of these gaps is resolved by adding a
second instance of an already purchasable source.

[Rule21 trade](oe54-trade.md) is a separate classic Rule6 descendant. It accepts
native Pottery only and does not inherit Original goods, Food or auxiliary
authority. Original Ceramics, Tea or Silk cannot be sold through that contract by
renaming their stock or relabelling a save.

## Requirements for a future chain

Before construction can be admitted, establish the exact producer/field identity,
complete footprint and parent lifecycle, legal source predicate, paid transaction
and staffing gate. Separately establish material identities, quantities, units,
productive timing, bounded storage and a genuine processing or consumption sink.
Unknown season, fertility, hunting and fishing behavior must remain unknown.

A World extension must use the existing navigator, typed ledgers, actual cargo,
incoming/return reservations and paid controls. It must preserve mass and Funds
through missing inputs, insufficient workforce/Funds, fire, pause, full buffers,
wrong parents/crops, occupied slots, road cuts, begun edges and rejected arrivals.
An authored transitional recipe requires its own explicit versioned contract;
it must not change older arrays, preparation requirements, rules or saves.

Acceptance then needs multiple paid production/consumption cycles, exact event
ticks and owner equations, F5/F9 and Recovery, independent full-document restore
and continuation, hostile-save refusal, and inspected production SandboxView
captures. Existing paid Rule18 retention is a historical control, not evidence
for an unimplemented crop.

## Reusable source checks

The read-only inspector uses the shared bounded model loader. Build the normal
test tree using the [testing guide](../testing.md), then run queries and focused
checks. Repeated queries retain only row identity and raw Cost/Employees/Resource
observations:

```sh
cmake --build build --parallel 2
./build/openemperor-model-inspect /path/to/emperor \
  --building 45 --building 192 --building 194
ctest --test-dir build --output-on-failure -R '^original-(model|production-model)-'
```

Use fresh ignored output paths when retaining JSON. Record the actual source
identity and distinguish raw values from prepared difficulty values. Missing,
malformed or unrepresentable queries must fail without publishing partial
observations; successful inspection does not confer World authority.

Run the full historical suite and generation-specific complete SaveDocument
comparisons, including the unchanged Rule18 paid Creator/Replay and the separate
demolition, source-cell ramp and trade continuations. New-chain gameplay, UI and
save acceptance are **NOT_IMPLEMENTED** here. Native and human acceptance remain
**NOT_RUN**; static source findings, synthetic checks and historical regressions
do not establish original end-to-end production parity.
