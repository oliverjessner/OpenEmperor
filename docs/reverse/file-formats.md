# File formats

The read-only SG3 inspector follows the published [SG file-format notes](https://github.com/bvschaik/citybuilding-tools/wiki/SG-file-format) and the independently published [layout specification](https://github.com/hansonry/sgfileio/blob/master/sgSpecification.md) as references. Its C++ implementation is independently written. Both sources describe little-endian SG metadata and separate `.555` bitmap data; the latter documents 200 reserved group slots for SG3.

For versions 213 and 214, the parser recognizes an 80-byte header, a 600-byte index, 200 reserved 200-byte group slots, and an image table beginning at byte 40,680. Image records are 64 bytes in version 213 and 72 bytes in version 214. It reads the header's declared image capacity and active group count, then checks every table range against the actual SG3 file size before reading it. Bytes after the declared image table remain unparsed.

Known header fields read at offsets 0, 4, 12, 16, 20, 28, 32, and 36 are reported with their published names. Header bytes 8–11, 24–27, and 40–79 remain unknown. The reported SG file size is displayed beside the actual size; a mismatch is not silently normalized.

Each active 200-byte group record supplies a bounded filename (0–64), description (65–115), dimensions (116–123), image count (124–127), and first/last image indices (128–135). Bytes 136–199 remain unknown and are output as hex.

Each image record supplies documented data offset/length, uncompressed-part length, dimensions, animation values, type and flags, and group ID. Version 214 adds alpha offset/length at bytes 64–71. The field at bytes 16–19 is deliberately reported as unknown raw hex: the two public sources describe it differently. Other undocumented spans are also output as unknown hex. Image bytes are never decompressed or rendered.

For an internal image, the inspector checks the same-stem `.555` file. For an image whose documented external flag is exactly 1, it uses the named group file with a `.bmp` extension changed to `.555`, resolved under the SG3 directory. Other flag values or unsafe/unresolved names are reported without inventing a source path. The metadata-only command opens no bitmap payload; it checks file existence, file size, and whether each data and alpha offset/length pair fits within that actual file size. Out-of-bounds ranges remain reported as out-of-bounds; no undocumented offset correction is applied.

The optional one-image exporter reads only a selected regular image with zero compression flags, no alpha-mask offset/length, and an encoded length exactly equal to width × height × 2. The public notes describe these pixels as little-endian 16-bit values with five bits per red, green, and blue channel; the [layout specification](https://github.com/hansonry/sgfileio/blob/master/sgSpecification.md) gives red at bits 0–4, green at 5–9, and blue at 10–14. The [SG notes](https://github.com/bvschaik/citybuilding-tools/wiki/SG-file-format) identify `0xf81f` as transparent. The exporter expands each five-bit channel to eight bits, emits row-major R, G, B, A bytes, and sets A to zero for that transparent value. It can write those bytes directly or package them as a PNG, following the [PNG specification](https://www.w3.org/TR/png-3/); PNG packaging introduces no new SG3 interpretation. The SDL3 preview reads the exported PNG only; it does not reinterpret SG3 metadata. Compressed, isometric, alpha-mask, and undocumented image types are rejected rather than guessed.
