## Service, lifetime and source binding

`maps::check_map_rules` is SDL-free. One opened `EmperorContainer` retains the bytes used both for SHA-256 and parsing. `SandboxPlacement` shares original manager/occupancy/gate/height validation between preflight and the actual producer. Preflight discards temporary claims; it never creates usable MapPermissions or a World and never fabricates a legacy building mask. Actual initialization applies the genuine legacy mask.

`MapRulesPreflight` owns one joinable worker, at most one active check, one latest pending request and one completion slot. Copied requests identify canonical root, relative map, profile, actual rule and policy. The main thread adopts results only when generation and selection identity match. Selection changes, leaving setup and shutdown invalidate old work. Shutdown joins the worker; no detached callback references a menu, View, World or SDL resource.

States are `Unchecked`, `Checking`, `MapRulesChecked`, `UnsupportedForRules` and `InputError`. Unknown class/schema and unsupported occupancy/gate conditions are support limitations. Missing/truncated/malformed files and invalid references are input errors, with **Check again** available. Obsolete results are neither displayed nor cached. Rejected entries remain selectable so their reason can be read.

Mouse Start and Enter share one central predicate. Unchecked, checking and rejected selections cannot enter expensive loading. Status changes disarm an existing mouse press. Existing valid sessions remain reachable through Continue and survive preflight or candidate failure.

The session cache holds at most eight terminal records, including content SHA. Remembered results are historical annotations, never Start authority. Every selection/recheck reads current bytes in the worker; polling/drawing do no parser or file work. Size/mtime are not trusted certificates. New starts compare the checked SHA against the loader's own container before graphics preparation, the permission loader's own container before combining claims, and current capture before candidate publication. Changed input rejects cleanly and returns to setup for a fresh check. These transient bindings add no save fields and alter no fingerprints.
