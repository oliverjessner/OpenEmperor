# OpenEmperor 0.1.0-alpha.2 candidate known issues

City-v16 rule 2 now uses consistent 2×2 Well/Herbalist geometry and identified static Safety sprites; rule-1 saves keep one-cell authority. Original building animation, fancy Well evolution, rotated/upgraded/terrain-transition road styles and original service mechanics remain outside scope. See [presentation audit](docs/reverse/original-presentation-correction.md).

City-v16 is opt-in and its ownership maintenance is authored balance, not reconstructed Emperor economics. The dry starter, overbuilt four-House comparison and an efficient eight-House city are measured separately; profitability still depends on real supply, Health, Fire and geometry. Debt has no limit, interest, bankruptcy or automatic shutdown. Numerical exhaustion rejects the tick before publishing economy mutations. Full native mouse-driven acceptance remains subject to the existing coordinate-input limitation; automated simulation and scripted SDL acceptance are reported separately. See [City-v16 validation](docs/city-v16.md).

City-v15 is opt-in; balance is authored and deterministic, with no original Emperor health parity claim. The historical 205-candidate one-cell audit incorrectly excluded the original 2×2 Safety buildings; legacy City-v15 still requires one-cell visuals, so the current authored pavilion and Health Worker marker are presentation previews. Long roads produce measured Health protection gaps; one Post does not guarantee 20 scattered Houses. No rule/default change was made to hide those gaps. The full 20–30 minute mouse-driven acceptance remains open: coordinate automation delivers incorrect SDL positions, while native keyboard actions and scripted SDL checks work. See [City-v15 validation and native acceptance](docs/city-v15.md).

- City-v14 proximity water is an opt-in OpenEmperor-authored prototype (rule 1/schema 16), not original Emperor water parity. It intentionally caps dry House levels without blocking actual supply, historical development or Level-0 tax income. The original 2×2 Well is identified for City-v16 rule 2; City-v14 retains its authored one-cell fallback. The authored fallback was redesigned for a quieter, period-consistent isometric presentation. A bounded 255-candidate original-asset review selected no convincing 1×1 Well; that historical scope cannot establish original Well identity. The fallback now uses a low faceted masonry ring, subdued interior water and thin offset timber supports, with the same geometry in alpha-128 placement preview. Local production-renderer City-v14 scene comparisons cover 1×/2×/4×. The existing House diagnostic overlay can cross raised timber like other neighboring sprites; the Well has no coverage tint. Older profile files remain valid and built-in original mappings are unchanged. The full 20–30 minute human mouse-driven acceptance remains open: coordinate automation throws `noWindowsAvailable`, while keyboard-controlled QA and synthetic SDL event tests work. City-v11 remains the default. See [City-v14 validation and test command](docs/city-v14.md).

- City-v13 now shows three curated effective House stages (1512/1516/1520), all 2×2. Original Emperor stage mapping and pivots remain unverified. Native city review covers all three candidate sequences at 1×/2×/4×; camera/selection are predefined, not a manual construction playthrough or independent perception study. Legacy-only/partial profiles retain fallbacks, and City-v12 and earlier keep their existing single House image. Whole-image depth sorting remains approximate. See [House evolution presentation](docs/building-visual-profile.md#city-v13-house-evolution-presentation).

- City-v13 residential desirability is an opt-in authored prototype (rule 1/schema 15), not original Emperor zoning parity. Only existing sandbox buildings contribute; map terrain, roads and House density have no direct score. A nearby Market/Service Post improves quality but grants no goods/coverage. Over-cap residents decline gradually, so population may exceed displayed capacity after an industry placement. The starter supports Level 1 on all four Houses and Level 2 on one. Actual native checks verify the transparent overlay and exact F5/F9/new-process restart, while synthetic tests verify two supplied districts and relocation. The full 20–30 minute native replanning/balance acceptance remains open: coordinate clicks in this session do not select Houses, though keyboard actions work. City-v11 stays the default. See [City-v13 validation](docs/city-v13.md#validation-on-2026-10-02).

- City-v12 fire safety is an opt-in authored prototype (rule 1/schema 14), not original Emperor fire parity. Incidents end naturally without destruction or goods loss. The exactly recognized asset set now supplies a curated 1×1 roofed civic-building preview for FireWatch; unknown/partial profiles retain its fallback. FireInspector deliberately remains a marker. The building’s original identity is unverified. Protection requires road-connected, staffed patrol and is not guaranteed across arbitrary large layouts. Burning Houses retain workforce until ordinary missed-demand decline. The full native 20–30 minute fire-expansion/recovery acceptance is still pending; City-v11 remains the default. See [City-v12 validation](docs/city-v12.md).

- Fire Watch now uses red-brick roofed record 383 instead of the rejected wall-like record 921. Native production-renderer review at 1×/2×/4×, two road-adjacent locations and F4 passes through a local comparison runner; camera/selection are predefined. This is not an independent viewer study or manual pointer-placement/demolition acceptance. The previous pass encountered `noWindowsAvailable`; broader native replanning acceptance remains pending. Adjacent whole-image artwork may partially obscure a Watch, with no footprint/anchor correction applied. See [replacement validation](docs/city-v12.md#fire-watch-visual-replacement-2026-10-02).

- Current source supports City-v11 v4 safe empty-building demolition through explicit copy upgrade/restore. New games retain v3 until native replanning acceptance. Stock, recipes and active/returning deliveries deliberately block removal; unmatched goods may require further supply to drain. No discard, refund or guaranteed recovery is implemented. Older v3 saves require an explicit copy upgrade.

- The complete native demolition/replanning playthrough remains pending: SDL event logging showed that the UI automation tool's coordinate clicks arrived at `(0,0)`. Keyboard actions work; core and SDL event tests passed. See [validation and manual acceptance](docs/testing-city-v11-v4.md). Finder/Gatekeeper launch and an independent clean-Mac test also remain unperformed.
- This alpha is an OpenEmperor sandbox, not Emperor gameplay parity.
- Original Emperor savegames are not supported. Only OpenEmperor sandbox saves are accepted.
- The automatic curated walker, building, and road preview is enabled only when all six files in one locally validated GOG-derived asset set match exact SHA-256 fingerprints. Other data revisions use presentation fallbacks.
- The bundled compatibility profiles contain only OpenEmperor metadata. They do not contain original pixels or other original game bytes. Their visual mappings, anchors, timing, and road topology remain curated preview conventions.
- Advanced custom JSON profiles can override each automatic category for one session. Invalid custom profiles fail explicitly; a damaged built-in profile falls back without blocking the sandbox.
- Presentation mode uses subdued diagnostic fallback colors. F1 exposes the brighter research diagnostics and technical visual-source status; this does not alter the World or save data.
- Whole-image depth sorting is approximate for overlapping original graphics.
- Elevation and many original map graphics are incomplete.
- Horizontal mirroring is parsed but not applied because its behavior is unverified.
- Some original animation timing and pivot semantics remain unknown.
- For the studied byte-59 flagged Omega walkers, OpenEmperor presents exact `0x7c00` shadow markers as 50% black RGBA. This closely models the verified original RGB555 destination-halving branch, but 8-bit source-over rounding is not bit-identical to its 5-bit framebuffer result. The behavior is deliberately limited to that verified sprite profile; an original-game side-by-side capture is still unavailable.
- The developer app is ad-hoc signed and is not notarized, so macOS may show a security warning.
- Only macOS on Apple Silicon (arm64) is currently supported and tested.
- A public source license has not been selected yet.
