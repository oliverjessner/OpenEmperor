# OpenEmperor clean-room rules

- The optional `curated_road_preview` is a session-only display mapping from four storage-neighbor bits to explicitly chosen physical SG3 Type-30 records. Keep `RoadTopology` SDL-free and read-only; adjacent sandbox buildings may provide visual entrance bits but never alter the World BFS road graph. Do not store mask/variant IDs, change road revisions, commands, saves or rule versions. Drag preview includes planned cells without mutating World. Missing masks retain yellow diamonds; invalid plans retain red diagnostics. F6 is independent of F2/F4. Keep each physical texture deduplicated, bounded, unmirrored and safely loaded through `src/assets/`. Local original profiles and decoded pixels remain under ignored `.local/`. No claim that this preview recovers Emperor's road IDs or selection logic; see `docs/road-visual-profile.md`.

- The opt-in macOS arm64 developer bundle is built from the existing `openemperor` target with `OPENEMPEROR_BUILD_MACOS_APP=ON`. Package only the app executable, its actual non-system dynamic dependencies and their license notices. Never stage the repository tree, `.local/`, original game files, decoded images, user settings or saves. Keep the normal non-bundle CLI target and `SDL_GetPrefPath("OpenEmperor", "OpenEmperor")` behavior unchanged.
- Run `tools/package_macos.sh` for a separate Release build, staging-only dependency fixups, inside-out ad-hoc signing, recursive Mach-O verification and relocated execution. An ad-hoc signature does not imply Developer ID, notarization or Gatekeeper acceptance. The repository currently has no explicit project LICENSE; do not invent one or treat this local preview as cleared for publication.

- The normal no-mode launch now enters one main-menu/session controller. Keep explicit CLI and headless modes independent of personal settings and dialogs. Original data remains read-only; validate required Terrain/Elevation SG3/.555 paths and a supported standalone map before accepting a data root. Store versioned application preferences and unique OpenEmperor sandbox saves under SDL's `OpenEmperor/OpenEmperor` preference path, never under original data or the repository. Keep dialogs asynchronous and callback state owned independently of views; ignore stale results. Preserve the existing save parser, map/session loader, simulation and save schema. A menu session retains the exact World when paused in the menu, and dirty replacement/exit requires Save, discard or cancel. Use only synthetic bytes and temporary preference roots in tests.

- The explicitly scoped `sandbox-logistics-v1` mode is now permitted gameplay. Its SDL-free `src/simulation/` core owns mutable prototype roads, buildings, goods, and courier state independently from read-only original map/SG3 data. `sandbox_buildable_v1` admits only candidate, on-map, exact `terrain_raw==0x80`, `objects_raw==0`, successfully rendered 1×1 footprint cells. This is a conservative local rule, not an original Emperor rule. Keep profile-specific constants, fixed tick order, BFS road routes, and the goods-balance invariant documented in `docs/gameplay-sandbox.md`; use synthetic fixtures in tests. Do not extend the sandbox into inferred original economy, additional file semantics, or mutation of user data.
- The explicit `sandbox-production-v2` profile extends that same SDL-free World and renderer with one Clay source, one Pottery building, one Warehouse, and two stable courier IDs. Keep both goods balances, active-recipe Clay, receiver reservations, route caches, and profile-specific command validation distinct. Clay must physically arrive before Pottery can start, and Pottery enters the Warehouse only on courier arrival. The start tick of a recipe gives no processing progress. Preserve the v1 profile and tests. These are authored prototype rules, not inferred Emperor semantics; see `docs/gameplay-sandbox.md`.

- This is an independently written open-source reimplementation. Never commit or distribute original Emperor game assets, the GOG installer, extracted game files, or proprietary Sierra/Impressions source code.
- Users must supply their own legally obtained Emperor game files. The first targeted distribution is the GOG offline installer; this repository does not ship or decode the installer.
- Keep local game files under `.local/` when practical. That directory is ignored by Git. Do not add test fixtures copied from proprietary files.
- Record reverse-engineering observations, provenance, evidence, and unresolved questions in `docs/reverse/`. Keep those notes separate from implementation code.
- Do not guess undocumented file-format semantics. Mark unknown fields explicitly unknown until evidence verifies them. Avoid treating names or interpretations from decompiled code as implementation specifications.
- Write readable, original C++20 code from documented behavior. Do not transliterate or paste decompiled/proprietary code.
- Preserve portability beyond the initial macOS arm64 target: use CMake, SDL3, and standard C++ where possible; isolate platform-specific code in `src/platform/`.
- The reusable `src/assets/` loader reads only selected `.555` color and alpha ranges into memory, without SDL or an inspector-tool dependency. Its supported color paths are documented plain RGB555, Omega Sprite types 256/257/276, and Type-30 isometric base with optional Omega color overlay in classic 58×30 or Emperor 78×40 geometry. The Omega alpha stream is applied afterward to straight RGBA, changing only A. The app renders the resulting image directly in SDL3; PNG debugging preview and inspector export remain separate options. Reject unsafe external paths, out-of-bounds effective ranges, malformed streams, and unsupported layouts. Keep `horizontal_mirror_offset` parsed but unapplied until verified; do not invent semantics or undocumented offset fixes. Do not import original or decoded assets into the repository or add game logic without a later scoped request.
- The metadata-only asset catalog uses relative SG3 paths plus image indices as stable IDs, sorts discovered archives deterministically, skips symlink escapes, and records malformed-archive errors without stopping. Its JSON may contain established metadata, never original pixels, decoded images, absolute local file paths, or guessed categories. Keep color-format support, payload bounds, alpha presence, and actual decode results distinct.
- The SDL asset browser decodes only visible images through the shared loader, retains at most 64 textures/64 MiB, and shows failures as placeholders. Its normal view includes the supported internal alpha profile only when the effective range is valid. `--ignore-alpha` is only a diagnostic color view; it must not change metadata or become the default.
- The test-scene viewer composes still images from the user's own SG3/.555 data using our versioned JSON manifest under `.local/scenes/`. Keep scene conventions in `docs/scene-format.md`, separate from observations about Emperor formats. Scene math and manifest parsing remain SDL-free. Use explicit anchors and only confirmed Emperor Type-30 footprint geometry; do not infer original map IDs, pivots, or mirroring. Do not add animation, walkers, building interaction, or simulation without a later scoped request.
- The scoped original-map reader in `src/maps/` may read user-supplied map and campaign containers only. Keep zlib container parsing separate from the verified map profile, impose file/part/block/output budgets, and distinguish physical file, part-relative physical, and uncompressed logical offsets. A container marker or filename extension alone does not prove a map. Preserve terrain and object words unchanged as `uint32_t` values; the 228×228 storage grid and declared map size do not establish playable cells.
- `TerrainInterpretation` and `MapGeometry` add only the documented, reference-derived rules over those raw words. Keep recognized flags, unknown bits, coarse category, rule, candidate diamond mask, and off-map bit separate. Do not turn a fertility bit into a numeric fertility level, an elevation bit into height, an object word into a building ID, or the reference bitmap transform into verified game-world coordinates. The SDL debug viewer retains both raw layers and labels semantic colors/projection as diagnostic. Its curated `textured` view uses only explicit bindings; the separate opt-in `stored-graphics` view displays saved graphic IDs under the studied runtime profile. Unsupported sizes remain raw storage-only. Do not commit original or decoded map bytes, invent repairs for mask mismatches, or add gameplay.
- `src/assets/Sg3PayloadLayout.*` is the shared production decision for loader, catalog, and inspector. The only supported alpha-bearing production profile is internal version-214 Type-256 with `alpha_offset == data_offset + 2 * data_length`, using effective alpha at `data_offset + data_length`. The stored relation is a profile marker, not a semantic explanation. Other alpha profiles are unverified and rejected by default; do not apply an external `-1` rule or automatic fallback. `src/assets/Sg3AlphaAudit.*` remains read-only historical research. Explicit `--alpha-addressing` and `--ignore-alpha` modes are diagnostics, never production defaults. Record evidence and limits in `docs/reverse/`, without embedding source bytes or rendered images.
- The textured original-map preview is now in scope, but only through explicit, bounded, local exact-pair bindings described in `docs/terrain-bindings.md`. Keep raw map cells, reference-derived terrain interpretation, and hand-selected SG3 preview graphics distinct. Never infer an SG3 index directly from a terrain word or claim that a curated assignment reproduces the original engine. Keep real binding files under ignored `.local/`; committed examples and tests must use synthetic records. Preserve every candidate storage cell (not minimap pixels), show unmapped cells diagnostically, and fail on broken referenced assets. Do not add coastline/variant/animation logic, heights, buildings, or simulation without a later scoped request.
- `MapGraphicCandidates` and `openemperor-map-graphics` preserve raw candidate words and bytes, their decompressed logical offsets, and unchanged terrain/object layers. A direct index into one SG3 archive remains a rejected hypothesis. The explicit `stored-graphics` snapshot may resolve saved words through `RuntimeArchiveLayout` for display; it does not prove the value survives to the original game's first draw. Keep metadata resolution, source bounds, supported footprint, actual decode, and visual inspection distinct. Do not mask high bits, modulo values, invent a combined archive space, or add an implicit curated fallback. Research observations belong in `docs/reverse/`; no local map dump, executable, or decoded original image belongs in Git.
- The bounded study of one original EXE permits explicit opt-in image-ID and resource-group diagnostics in `src/maps/`; their corrected evidence and historical errors are in `docs/reverse/graphics-id.md`. For the studied v213 Terrain/Elevation registrations, the first **internal bitmap-group filename** is compared with `Zeus_system.bmp`. A match activates a literal 200-record skip in addition to physical dummy record zero. `RuntimeArchiveLayout` is the shared, SDL-free model: local image `i` maps to physical record `system_skip + 1 + i`, bounded by `reported_images_in_use - system_skip`; physical `AssetId` numbering never changes. It also filters SG3 index words by signed value minus skip and retains them in file order because the observed list keys increase with file positions. Do not revive the superseded `i+1` or reversed-group assumptions for these archives. Keep group keys distinct from packed image IDs, reject unknown slots/versions/contexts, and never apply skips twice.
- The `0x603` group query and its eight supplied variants are diagnostics for a **pre-read** writer, not a post-load terrain selection rule. The studied map-load path replaces the generated per-cell graphics array with stored words; later writes before drawing remain unresolved. Preserve saved IDs and the separate auxiliary byte layer at logical offset 729311; never use the group result as a fallback map texture or infer generator state from it. Static research may use a locally supplied EXE read-only; keep originals, full disassemblies, decompiler output, and analysis projects ignored under `.local/`.
- `StoredGraphicsPlan` and `StoredGraphicsRenderer` are a diagnostic saved-ID map snapshot. Preserve one raw record per candidate storage cell and resolve physical AssetIds only through the shared runtime layout. The default view draws supported 78-wide one-cell Type-30 footprints. The separate `--multi-tile-preview` option may group only an isolated, complete 2×2 component of identical saved IDs with confirmed 158-wide, 12,800-base-byte, size-flag-2 Type-30 geometry. That is an explicit preview convention, not a proven original draw anchor or `candidate_byte` meaning. Keep touching, incomplete, mask-boundary, conflicting, mirrored, unsupported, or failed cases diagnostic; do not invent partitions, heights, or original first-draw rules. Four owned cells remain independently selectable and produce one placed instance, with one decoded texture shared across instances. Preserve path and 2,048-asset/16-MiB-image/64-MiB-logical-RGBA budgets, no per-frame decode, and independent curated bindings. No original or decoded asset may be committed.
- The additional `--footprint-policy edge-byte` requires `--multi-tile-preview` and is a separate reference-derived 2×2 experiment. Keep the old isolated policy unchanged. Retain the candidate byte, unknown high bit, and marker candidate independently; validate signed origin, exact four parts, same saved ID and physical AssetId, source and geometry before ownership. Do not interpret the marker as a verified original draw anchor, use the separate auxiliary byte layer, or fall back to isolated grouping on malformed metadata. Keep this policy opt-in until Emperor's low-bit semantics are independently established.
- The standalone map browser and noninteractive compatibility check share `MapCatalog`, `StoredMapSession`, the existing saved-graphics plan, decoder, and renderer. Catalog records begin `not_checked`; a successful `snapshot_complete` means two OpenEmperor frames and complete *candidate-mask* coverage only, never original-game fidelity or first-draw proof. Keep per-map failures and unsupported cells explicit, avoid changing format rules to improve corpus statistics, and save local corpus reports only under ignored `.local/reports/`. Browser map sessions must release owned SDL textures before another map opens; no global cache of decoded maps, original pixels, or map dumps belongs in Git.
- The explicit `exe-6373328b-v213-slot8-runtime-table` profile extends the base Terrain/Elevation registration with only slot 8 (`DATA/China_Mon_Earthen_Greatwall_1.sg3`) when a candidate cell references it. This mapping comes from the hash-checked local EXE registration path, not archive order. Its v213 archive must match the observed `Zeus_system.bmp` 200-record group before the shared dummy/system translation is used. Keep the base profile stable; missing optional archives and unsupported layouts stay distinct diagnostics. The separate opt-in `edge-byte-4x4` footprint policy extends the existing metadata preview to confirmed 318-wide, 51,200-base-byte, size-flag-4 Type-30 images only. Require all 16 exact parts, same saved ID and physical AssetId, contained nonconflicting claims, valid source, and no mirror before assigning ownership; keep 1×1/2×2 and the old policies stable. The marker remains diagnostic and `0x80` unknown. A complete 4×4 instance draws the full decoded image once while every raw cell remains selectable. This is a saved-snapshot preview, not proven original first-draw composition. See `docs/reverse/graphics-id.md` for evidence and limits.
- OpenEmperor sandbox saves are an own, versioned JSON format for all scoped rule profiles, never original Emperor savegames. Keep the typed authoritative `WorldSnapshot` in `src/simulation/` and file/JSON/SHA-256 handling in `src/persistence/`. Save active paths, edge progress, cargo, reservations, recipes, stock and counters; rebuild occupancy, owner indices, and future route caches without replay or advancing a tick. Validate the original map hash and post-decode buildability mask before publishing a loaded World. Save only outside the original `--data` root, via checked temporary-file replacement; no original map/SG3/.555 bytes or decoded assets belong in saves or tests. F5/F9 use one configured path; successful load pauses at the exact saved tick. Keep the old finite check read only and gate its temporary file roundtrip behind `--sandbox-resume-check`.
- Road removal is limited to `sandbox-production-v2` rule version 2 and `sandbox-household-v3` rule version 1 and `sandbox-settlement-v4` rule version 1 and `sandbox-industry-v5` rule version 1; the v1 logistics profile explicitly rejects it. Protect a courier's occupied road at a waypoint and both endpoints of a begun edge, including the other couriers. Removing a future road may invalidate only the remaining active route, never the phase, real position, cargo, or target reservation. Reroute from the reached waypoint through placed roads only, retaining deterministic BFS order and allowing a two-point road-to-goal finish; do not replace a valid active route on placement. Failed searches wait until a changed road revision, and returners cannot teleport. Keep topology counters and waiting/edge state authoritative in schema-4/5 saves, allow removed historical road cells in validated paths, and read known schema-1/2 saves via explicit compatibility paths. The original map and graphics remain read only. These authored sandbox rules are not claims about Emperor walkers or demolition.

- The explicit `sandbox-household-v3` profile adds one one-cell Household and a third Warehouse-to-Household Pottery courier to the same World. Goods leave the warehouse only at courier dispatch, reserve household space while in transit, and enter household stock only on arrival. A placed household evaluates one demand every 400 subsequent integer ticks, consumes at most one stored Pottery, and records fulfilled or missed demand without debt. Preserve the v1/v2 profiles, shared BFS and protected road-removal rules, exact cargo/reservation balances, and schema-3 compatibility with schema-4 save/load; old schema-1/2 saves keep their original profiles. Keep the original map and graphics read only. These are authored prototype rules, not original Emperor housing behavior.
- The opt-in `sandbox-settlement-v4` rule version 1 extends the same SDL-free World to at most four independent Household instances. Keep production building IDs 1–3 and stable Household IDs 4–7; allocate only after successful placement, never reuse IDs, and retain v3's one-house limit. One warehouse supplier selects an eligible reachable, non-full house cyclically after the last successful dispatch, with target-specific routes keyed by topology revision. A running or waiting delivery keeps its concrete target and that house's sole reservation; selection diagnostics must be pure. Every house owns its stock, placement tick, 400-tick need clock, results, and consumption. Sum all houses in Pottery conservation without increasing production or adding couriers. Schema 4 stores all canonical building records, next ID, selection cursor, active target and routes; schema 1–3 imports preserve their old profiles and ID 4. Keep the real map and graphics read only. These distribution rules are authored sandbox behavior, not reconstructed Emperor economics.
- The opt-in `sandbox-industry-v5` profile expands the same World to at most two Clay sources, two Pottery works, one warehouse and four houses. IDs 1–7 remain stable; allocate IDs 8/9 and couriers 4/5 only on successful second-producer placement, storing kind and courier role explicitly. Process all Clay sources by ID, then all Pottery works by ID, then house demand, dispatch, movement and invariants. Every source owns a Clay courier and a private cyclic Pottery target cursor; each works owns a Pottery courier. Retain the single shared house supplier. Cache source-to-target routes by topology revision, keep active targets fixed through waits, and sum concurrent inbound reservations by actual target. Count source extraction and completed recipes per works and reconcile with global Clay/Pottery conservation, inventories, courier cargo and consumed household goods. Schema 5 saves canonical nine-building/five-courier state including roles, cursors and next IDs; schemas 1–4 retain their prior profiles and must not gain phantom producers. Keep original maps and graphics read only. These are OpenEmperor sandbox rules, never claims about original Emperor production.
- The sandbox UI uses one action path for buttons and keyboard. Keep layout, hit testing and road planning separate from simulation rules. A road drag previews an X-then-Y path of at most 256 cells, then revalidates and applies only new PlaceRoad commands to a temporary World at release; publish it only after every command succeeds. UI presses, invalid paths, focus loss, resize, right click, Escape and tool/save/load changes must not leak map commands. Clip drawing to the map rectangle and restore SDL viewport, clip and scale before event coordinate conversion. Selection stores an ID or cell, never a pointer into a replaced World. UI state stays out of schema 1–5 saves, and the original map and graphics remain read only.
- Optional `curated_walker_preview` profiles are presentation-only and local to an app session. Reference physical SG3 image records by data-root-relative archive path; do not apply runtime-table skips or infer Emperor walker registrations from group names. `WalkerPose` derives Clay-courier direction from the authoritative current path edge and selects frames only from World ticks. Waiting/idle is static; unmapped directions remain diagnostic markers. Use independently chosen per-frame foot anchors, the shared SG3 decoder, and one SDL texture per distinct referenced image across both Industry Clay couriers. Keep the 1 MiB manifest, 256-frame, 64-entry/clip, and 64 MiB RGBA budgets and reject path/symlink escapes, malformed frames, and unsupported mirror layouts. Profiles, decoded frames, and original data stay outside saves and bundles. Document visual evidence and unknowns in `docs/reverse/`; the preview timing and anchors are not original-game facts.
- The optional `curated_building_preview` is a separate, session-local display profile for ClaySource, Pottery, Warehouse and Household. Each optional role references a physical, unmirrored Type-30 SG3 record through the shared decoder; do not translate physical IDs or infer original building IDs, footprints, states, animations or pivots. The configured ground anchor positions the whole image over the authoritative one-cell BuildingState, without changing occupancy, paths, recipes or saves. Deduplicate decoded images and SDL textures by AssetId across roles and instances within a bounded budget; failed profile changes leave the running view intact. F4 switches all configured building visuals independently of F2. Valid placement previews use the same anchor with partial alpha and do not mutate World. Keep original pixels, local manifests and decoded output ignored and out of bundles.
- Sandbox rendering uses one preview-only ground-depth key for stored map instances, roads, buildings and walkers: depth, projected x, layer (StoredMap < Road < Building < Walker), stable ID. `terrain_ground` adds 20 to the unchanged `terrain_world` top point for sorting only. Stored items are sorted once and retain their textures, culling and diagnostics inside `StoredGraphicsRenderer`; dynamic sandbox items are sorted per frame and linearly merged. Draw selection, hover and invalid placement after the merge. F7 selects the legacy whole-map-first comparison; unified is the default and neither mode changes World, commands or saves. This does not prove Emperor's original draw order, split sprites or Z semantics.
- The bounded local `SprMain.sg3` follow-up supports four visually selected Storage-direction clips without assigning an Emperor profession or format-level direction field. The F3 diagnostic panel may step those clips, change 1×/4× and dark/light display, and show frame/anchor bounds without advancing the World. Keep its visual-only selection separate from live tick-based `WalkerPose`. Physical record 109's red area is an opaque `0x7c00` Omega color literal in the current normal decoder, with no alpha payload; its intended original-game treatment remains unknown. Do not add a red chroma key, alternate alpha address, mirror rule, or global channel change without independent evidence and a prior failing regression. Machine checks must distinguish configured, decoded, actually drawn, and manually reviewed directions.
